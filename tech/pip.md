# pip, virtual environments and the lock files

## What it is

**pip** is the program that installs Python libraries from the Python Package Index (PyPI), the public shelf of Python packages. A **virtual environment** is a folder (here `.venv/`) with its own interpreter and its own installed libraries. A **lock file** is a text file that lists the exact version of every library to install, so every machine gets the same ones. This repository uses **pip 26.2.2** (the version that came with the Python 3.13 venv on the verification machine) and two lock files: `requirements.lock` and `requirements-dev.lock`.

## Why this repository uses it

A security project must be reproducible and must not install something unexpected. Each lock file pins every library and every transitive library (a library that another library needs) to one version, and records the **hash** (a fingerprint) of each downloadable file. pip with `--require-hashes` refuses to install a file whose fingerprint does not match.

## Where it appears

| Path | What it does |
| --- | --- |
| `requirements.lock` | the libraries the function needs at run time (boto3 and what it needs) |
| `requirements-dev.lock` | the run-time libraries plus the development tools (pytest, pytest-cov, ruff, mypy, import-linter and pip-audit) and every library they need |
| `Makefile` | the `$(STAMP)` target creates `.venv` and installs from the dev lock |
| `.github/workflows/ci.yml` | CI runs `make`, which does the same install |

## How it works underneath

`python -m venv .venv` copies (or links) the interpreter into `.venv/bin/` and creates an empty folder for libraries. `pip install` downloads a **wheel** (a ready-to-unpack archive) or a source archive from PyPI, checks it, and unpacks it into the venv's `site-packages` folder. A **hash** is the SHA-256 fingerprint of a file: change one byte and the fingerprint changes. `pip install -e .` ("editable") installs this project itself by linking to the source folder, so edits take effect without reinstalling.

## Walkthrough of this repository's use

**What pip and a lock file are.** `pip` is Python's package installer: given the name of a library it downloads the library from the public index (PyPI) and installs it into the Python environment it belongs to. A **lock file** lists *every* library the project needs, directly or indirectly, each at one exact version, with a fingerprint of the files it may be installed from. Installing from a lock file gives every machine, and the CI, exactly the same libraries, byte for byte, and protects against a library being replaced by a tampered copy. The lock file is produced by a tool ([uv.md](uv.md)); nobody edits it by hand.

From `Makefile` (lines 21 to 25):

```make
$(STAMP): requirements-dev.lock pyproject.toml
	$(PYTHON) -m venv $(VENV)
	$(VENV)/bin/pip install -q --require-hashes -r requirements-dev.lock
	$(VENV)/bin/pip install -q --no-deps -e .
	touch $@
```

This rule builds a **file**, not an action. The target is `$(STAMP)`, which is `.venv/.installed`. Its prerequisites are the lock file and `pyproject.toml`: if either is newer than the stamp, the recipe runs again, otherwise `make` does nothing. That makes every other target that needs the environment cheap to repeat. The recipe has four lines:

- `$(PYTHON) -m venv $(VENV)` creates a **virtual environment**: a private folder (`.venv/`) holding a copy of the Python interpreter and its own set of installed libraries, so this project's libraries cannot collide with any other project's. `-m venv` means "run the module named `venv` that ships with Python".
- `$(VENV)/bin/pip install -q --require-hashes -r requirements-dev.lock` installs every library from the lock file into the environment. `pip` is Python's package installer. `-q` is quiet. `-r FILE` reads the list of requirements from a file. `--require-hashes` makes `pip` refuse any library whose downloaded file does not match the fingerprint recorded in the lock file ([pip.md](pip.md)).
- `$(VENV)/bin/pip install -q --no-deps -e .` installs *this project* in **editable** mode (`-e`): the environment points at the source folder instead of copying it, so edits take effect at once. `--no-deps` stops `pip` from looking for dependencies, because the previous line already installed all of them exactly.
- `touch $@` creates the empty stamp file `.venv/.installed`, which is how `make` remembers the work is done.

The two `pip install` lines are the only places `pip` runs in this repository. The first installs the whole lock; the second installs the project itself without touching the libraries.

From `requirements.lock` (lines 1 to 2):

```text
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --universal --generate-hashes --python-version 3.12 -o requirements.lock
```

The first two lines are comments written by the tool that produced the file: they say which command created it. `uv pip compile pyproject.toml ... -o FILE` read the project's requirements from `pyproject.toml` ([toml.md](toml.md)), worked out every library that is needed, and wrote the result to this file. The flags: `--universal` makes one lock that works on every operating system; `--generate-hashes` records the fingerprints; `--python-version 3.12` resolves for the oldest supported Python. This lock has no `--extra`, so it holds only what the program needs **when it runs**.

## Try it yourself

```bash
.venv/bin/pip --version
```

Expect `pip 26.2.2 from .../.venv/lib/python3.13/site-packages/pip (python 3.13)`.

```bash
.venv/bin/pip show cloud-security-detect-and-respond | sed -n 1,3p
```

Expect the project name, `Version: 0.1.0` and its summary: the editable install.

```bash
.venv/bin/pip list | sed -n 1,5p
```

Expect a table of installed libraries; `boto3 1.43.119` is among them.

```bash
grep -c "^    --hash" requirements.lock
```

Prints `14`: the number of fingerprints the run-time lock holds.

## Mistakes people make

- Installing with plain `pip install boto3`, which takes whatever version is newest today. Use the lock.
- Editing a lock file by hand. Regenerate it with `uv pip compile` instead (see [uv.md](uv.md)).
- Running pip outside the venv and changing the system Python. Use `.venv/bin/pip`.
- Forgetting that `--require-hashes` needs every dependency listed. That is why the lock includes transitive ones.

## Check yourself

1. What is a lock file for? *To pin every library to one version so installs are identical.*
2. What does `--require-hashes` do? *Refuses to install any file whose fingerprint is not listed.*
3. What does `-e .` do? *Installs this project in editable mode, linked to its source folder.*
4. Why is `--no-deps` used on the second install? *The dependencies are already installed from the hashed lock.*
5. What does `touch $@` do in the Makefile? *Creates the stamp file that records the install is up to date.*
